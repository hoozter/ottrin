# Discharged destination claims

The prior ledger appended a new generation whenever old terminal Copy journals still existed. This grew historical bookkeeping and exposed later Claim appends to partial writes. The authoritative constructor now prepares every reservation privately and publishes a complete first frame by native held-handle no-replace rename.

## Authority and lifetimes

An active/nonterminal journal still requires its exact native claim file and binding. Claim release is terminal only after complete Undo (including original restoration) or durable cleanup start. Forward completion alone does not release a name.

Snapshot loading independently validates paired journal bytes, identities, namespace, security and phase before observing an optional terminal claim. If the original control remains, its contents and metadata must still validate; unknown tails and streams are preserved. If its canonical file is absent or has a different native identity, terminal recovery holds no name capability. It neither parses nor mutates another owner's file. A missing claim cannot bypass nonterminal or mismatched paired evidence.

Writers revalidate paired evidence before reopening any pending old claim. Both journals remain leased through authorized release. The explicit Activity release action is available only for the original pending claim; stale actions refuse a new owner.

Cleanup dependency references continue to protect all recorded claim identities. Those references are identity sets, not an obligation to reopen obsolete files. Payload deletion retains its separate held-native-tree, metadata, manifest and peer-dependency checks. Old terminal cleanup can complete while a new reservation writer remains live, without changing that writer's bytes or identity.

## Bounded ledger

Claim format 3 permits exactly one initial Claim and one Release. A complete released control may be retired after its metadata, streams, link count, native binding and namespace are revalidated. New admission always uses complete private preparation and no-replace publication. There is no historical append or old-registry scan for released controls. Abandoned active cancellation still requires an exclusive writer and absence of both canonical recovery records, resolving its registry by native identity.

Journal format 17 records this changed lifetime contract. Older experimental formats are not migrated. The public Windows Copy entry point remains closed, and this job does not rebuild or promote application packages.

## Verification

Native cases cover a live new reservation throughout old terminal Undo and cleanup; missing and foreign controls; mismatched paired state; old release actions encountering newer partial releases; every exact interrupted Release prefix; crash/I/O boundaries; constructor publication races; and existing cleanup-start controls. The first focused run found one obsolete historical-append assertion. Its 30-pass/1-fail result is retained separately and is not acceptance. Final executable/hash-bound results are authoritative for the completed checks.

Remaining work includes retirement-specific process-exit/race coverage, abandoned private preparation collection, partial root/stage construction, physical-power behavior, resource/alias/ancestor and full workflow/package gates. This is a component checkpoint in the full roadmap.
